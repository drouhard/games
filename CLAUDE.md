# CLAUDE.md

Rules for working in this repo. One line each.

## Git

- Never leave a pull request for the user to review or merge — merge it yourself and push.
- Develop on the assigned `claude/...` branch, then merge that branch into `main`.
- Merging to `main` is the deploy; work isn't delivered until `main` is pushed.

## Hosting

- GitHub Pages serves the `main` branch from the repo root — there is no other deploy step.
- Never suggest running a local server; the user plays at the Pages URL, not on their Mac.
- Use relative paths in every `href` and `src` — the site is served under `/games/`, not at the domain root.

## Constraints

- No back end, no build step, no dependencies, no package manager.
- Plain HTML/CSS/JS that runs exactly as committed — no transpiling, no bundling.

## Structure

- One folder per game under `games/<name>/`, fully self-contained.
- The only shared code is `shared/base.css`; games never import each other.
- Add every new game as a card in the root `index.html` launcher.
- Icons are generated by `tools/make-icons.py` — regenerate, don't hand-edit the PNGs.

## Games

- Target iPhone Safari: the play area must fit portrait and landscape with no scrolling.
- Put any new iOS workaround in `shared/base.css` so the next game inherits it.
- Before committing, drive the page in a headless browser at iPhone dimensions and actually play it.
